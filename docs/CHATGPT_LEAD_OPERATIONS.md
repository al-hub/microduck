# Microduck ChatGPT Lead 운영 계약 — #10

## 목적
ChatGPT가 요구사항과 수용 기준의 책임자(Lead)로서 PC AI를 선택·위임하고, 테스트 결과를 독립 확인한 후 GitHub 이슈·PR과 로컬 상태를 동기화한다. 모든 단계는 실제 실행 증거가 있을 때만 완료로 판정한다.

## 요청부터 종료까지 7단계
1. **진입:** `AI.md`, `notes/STATUS.md`, 대상 GitHub 이슈·PR·최신 검증 증거 확인.
2. **계획:** 요구 ID, 수용 기준, 변경 영향, 위험 등급(R0~R4), 작업 디렉터리와 비용 상한을 명시. 요구 변경은 이력 남기기.
3. **할당:** 단일 도구 우선. 로컬 작은 순수 함수는 Ollama 후보; 충분한 격리 및 인증이 있을 때 AGY/Codex/OpenCode를 선택. 독립 리뷰에만 추가 모델 사용.
4. **개발:** 격리 worktree, TDD Red→Green→Refactor, diff/hash 및 종료 코드 기록. 에이전트 반환 문장만으로 성공 판정 금지.
5. **검증:** 독립 테스트·보안/비밀정보 검사·성능 측정·다른 에이전트 리뷰. 인증/사용량/timeout은 명시적 실패로 처리.
6. **반영:** 운영 변경 전 백업과 복구 계획. 코드 변경은 PR→CI→검토→병합, 배포 후 별도 스모크. 사용자 승인 없는 R3/R4 변경 금지.
7. **인수인계:** GitHub #10과 `notes/STATUS.md`의 상태/차단 사항/다음 명령을 동기화. 다음 대화가 중단된 단계부터 재진입.

## 상태 모델
BACKLOG → READY → IN_PROGRESS → REVIEW → VERIFY → DONE. 실패·승인·인증은 BLOCKED.
완료 기준: 요구 충족 + 실제 결과 + 테스트 + 검토 + GitHub 증거. 상태와 체크박스를 혼동하지 않는다.

## 에이전트·폴백 정책
- AGY: 코딩 후보. 내부 `print timeout`인 경우 완료가 아닌 불완전으로 표시.
- Codex: 코드 리뷰/코딩 후보. NVM Node PATH는 실행 프로세스에만 주입, 권한은 read-only/sandbox 기본.
- OpenCode: 기본 `build/beam-free` 검증됨. `plan` 인증 오류 이력이 있으므로 자동 동일 재시도 금지.
- Ollama: 코드 초안/로컬 보조 후보. 생성 코드를 그대로 실행하지 않고 AST/검토/격리 테스트 후 수용.
- 동일한 장애에 무제한 재시도하지 않는다. 비용·토큰 불명확시 '미측정', 비용 0 추정 금지.
- 네 AI 전부 실패해도 요구와 증거는 유지하고 BLOCKED. 성과를 허위 완료하지 않는다.

## 운영 실행 경계
R0 문서/상태 읽기, R1 고정 검사, R2 OS 격리된 코드 변경, R3 설치/서비스/공개 변경, R4 고위험 관리자·물리 제어.
`tools/mcp/dev_tasks.py`는 **R1용 로컬 모듈**이며 현재 live MCP tool로 등록되지 않았다.
명령 basename 목록은 OS 샌드박스가 아니다. 개발 에이전트는 별도의 경로·네트워크·비밀·자식 프로세스 제한이 확인되기 전 운영 환경에 무제한 호출하지 않는다.
