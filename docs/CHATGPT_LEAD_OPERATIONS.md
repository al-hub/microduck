# ChatGPT Lead — Microduck PC 도구 활용 운영 가이드

## 운영 정의
ChatGPT가 요구사항 판단, 개발 진행, 테스트 결과 검증, GitHub 기록의 책임을 지며 **PC AI는 필요한 때 선택해서 사용하는 도구**다. 별도 자율 멀티에이전트 오케스트레이터를 만들지 않는다.

## 기본 흐름
1. 사용자가 'Microduck 작업하자' 등으로 요청.
2. ChatGPT는 PC `AI.md` → `notes/STATUS.md` → 관련 GitHub 이슈/PR을 확인하고 필요한 요구사항·수용 조건을 정리.
3. ChatGPT가 직접 가능한 작업을 우선 수행한다. 긴 생성/다른 관점 검토가 유용할 때만 AGY, Codex CLI, OpenCode 또는 Ollama를 호출.
4. 실제 파일/diff, 테스트 종료 코드, 오류를 독립 확인. TDD·SOLID는 코드 개발 기준으로 사용하며, **매 작업마다 네 AI를 모두 호출하지 않는다**.
5. 변경된 요구사항과 검증 결과를 해당 이슈/PR 및 PC `notes/STATUS.md`에 요약해 다음 대화에서 바로 이어간다.

## 도구 선택
- Antigravity: 코드 작업 및 분석 후보. 실행 시간 초과라면 결과를 실제 파일로 확인.
- Codex CLI: 필요시 구현 또는 독립 리뷰. NVM Node 경로를 해당 실행의 PATH에 주입하는 방식이 검증됨.
- OpenCode: 기본 build 모델의 읽기/리뷰 확인. plan 모델 인증 오류는 해결되지 않음.
- Ollama: 로컬 추론·초안 생성. 생성 코드의 정확성과 안전성 검증 후 사용.
- 한 도구로 충분하면 다른 도구 호출 생략. 토큰/비용 미측정은 미측정으로 표시.

## 권한과 안전
- 기존 Microduck MCP 허용 경로와 인가 규칙을 지키고, KUM·ClosePaw 및 upstream 변경은 별도 승인.
- 인증·관리자 권한·설치·업데이트·재부팅·외부 공개는 위험에 따라 사용자 승인.
- 명령 이름 allowlist만으로 완전한 OS 샌드박스가 성립하지 않으므로, 미검증 생성 코드·위험 명령은 적절한 격리 없이는 실행하지 않는다.
- `tools/mcp/dev_tasks.py`, `scripts/command_policy.py`는 검증용 **초안**이다. 운영 MCP에 연결되었다고 주장하지 않는다.

## #10 간소화 수용 조건
- ChatGPT ↔ PC MCP의 기본 읽기·실험 편집·테스트 통로가 실제 작동
- 네 AI 도구가 필요시 호출 가능한 것을 최소 수준 실증하고 제약을 문서화
- ChatGPT 주도 소규모 개발→테스트→독립 리뷰 실제 예시 확보
- 운영 지침/작업 상태/이슈 기록과 다음 채팅 재개 흐름 정리
- PR 코드와 문서를 검토하고 실제 확인한 결과만 완료 표시

## 후속 개선 (이번 필수 범위 아님)
- 네 AI 각각의 완전한 자율 TDD 파이프라인
- 별도 라우터/복잡한 에이전트 병렬화/과도한 통합 대시보드
- 무인 버전 업데이트·자동 롤백·Windows 재부팅 복구
- OS 샌드박스 플랫폼 자체 구축 (위험도가 높은 작업에는 적절한 격리가 별도로 요구될 수 있음)
