# Microduck #10 — MCP 실행 권한 및 격리 정책 (초안 v1, 2026-10-24)

## 목적과 현재 적용 상태
이 문서는 승인 대상과 시험 범위를 정의한다. **운영 MCP에 적용된 정책이 아니다.**
현재 `run_command`의 실행파일 이름 허용 목록은 샌드박스가 아니며, `python3 -c` 및 도구 자체의 하위 프로세스 생성 등으로 명령/파일/네트워크 접근이 확대될 수 있다.

## 1. 실행 권한 등급
| 등급 | 내용 | 대상 | 승인/운영 |
|---|---|---|---|
| R0 | 버전·상태·제한된 파일 읽기 | 등록된 프로젝트 문서/상태 | 기본 허용(비밀·외부 경로 제외) |
| R1 | 사전에 등록된 문법/테스트 실행 | 격리 실험 디렉터리 | 정확한 명령 템플릿, 고정 cwd, timeout, 로그 |
| R2 | AI의 파일 생성/수정·테스트 | 각 도구별 별도 disposable 작업트리 | 독립 컨테이너/OS 격리 실증 후만 허용 |
| R3 | 의존성 설치·업데이트·서비스 재시작·Git push | 운영 환경 | 변경 범위/백업/복구계획 확인 후 개별 승인 |
| R4 | sudo, 전체 파일시스템, 자격증명 열람, 무제한 승인, 물리 로봇 구동 | 운영 PC | 기본 금지, 별도 사용자 명시 승인 및 추가 안전 검증 필수 |

## 2. 경로·데이터 경계
- 쓰기 허용 후보: `experiments/agent-smoke/` 아래의 **에이전트별 서로 다른 격리 디렉터리**.
- 읽기 기본 허용: 필요한 `AI.md`, 테스트 규격, 해당 실험 소스. `upstream/`, ClosePaw, KUM은 변경하지 않는다.
- `~/.ssh`, `~/.config`, `~/.gemini`, 인증 토큰, 개인 데이터, 터널 비밀 파일은 에이전트에게 마운트/전달하지 않는다.
- 모든 실제 모델/코딩 호출은 가능한 한 별도 비밀 없는 사용자·홈, 읽기 전용 루트, 제한된 쓰기 마운트, subprocess 포함 프로세스 제약, 네트워크 기본 차단, 리소스/시간 제한으로 격리한다.
- CLI 인증이 필요한 경우에도 호스트 비밀을 무조건 전달하지 않는다. 허용된 짧은 수명의 인증·프록시 구조를 별도로 검토하고, 없는 경우 BLOCKED 처리한다.
- Python 코드 내 필터나 명령 basename 검사만으로 R2가 안전해졌다고 판정하지 않는다.

## 3. 명령·출력 정책
- 실서비스에서는 임의 셸(`bash -c`), `python -c`, `node -e`, `npm run`, Git `-c`/외부 hook 등의 범용 실행 표면을 직접 열지 않는다.
- 도구별 전용 명령 템플릿과 argv의 의미 검증을 사용한다. 절대경로 실행도 동일한 정책을 적용한다.
- `--dangerously-skip-permissions`, `--auto`, `--yolo` 등 무제한 승인 옵션은 금지.
- stdout/stderr 개인정보·키 패턴 마스킹, 출력 길이 제한, 시간 초과 시 프로세스 그룹 전체 종료, 종료 코드/경과시간 기록.
- 모델 요청이 네트워크를 요구한다면 허가된 도메인/소켓으로만 제한하며, 로컬 Ollama는 별도 정책을 적용한다.

## 4. Codex PATH
- 확인된 위치: `/home/al-hub/.nvm/versions/node/v24.15.0/bin/{node,codex}`.
- `codex`의 `#!/usr/bin/env node` 실행 문제는 **해당 subprocess에만** `PATH=<NVM_BIN>:/usr/bin:/bin`을 주입하는 방식으로 해결 가능(기존 0.160.1 exit 0 증거).
- 전역 PATH, NVM 설정 또는 systemd Environment 변경은 R3 별도 검증 전에는 하지 않는다.

## 5. 독립 코딩 TDD 수용 기준
1. 각 AGY/Codex/OpenCode에 같은 함수 명세와 **각자 다른 작업트리** 제공.
2. 구현 전 테스트 실패(Red), 구현의 실제 파일/해시/Git diff, 테스트 성공(Green), 별도 Refactor diff와 회귀 테스트를 확인.
3. 다른 에이전트는 read-only 리뷰; 구현자가 수정한 경우 재테스트 및 diff 검토.
4. exit 0이나 AI의 성공 문구만으로 완료 처리 금지. AGY 내부 print-timeout 등은 불완전 실행으로 분리.
5. 토큰 수치가 노출되지 않으면 `미측정`으로 표시하고, 비용 0이라고 가정하지 않는다.

## 6. 안전한 배포 게이트
- 정책 테스트 → 독립 샌드박스 탈출/네트워크 차단 부정 테스트 → 제한된 스모크 테스트 → 설정 백업 → 서비스 변경 → 서비스/터널 건강 상태 → 외부 ChatGPT 재호출 → 실패 시 롤백.
- 현재 `scripts/command_policy.py`는 **정적 검증 초안**이며 이 게이트를 충족하지 못했다.
- 서비스 재시작, Windows 재부팅, 모델 업데이트, GitHub PR/병합은 각각 별도 성공 증거가 필요하다.
